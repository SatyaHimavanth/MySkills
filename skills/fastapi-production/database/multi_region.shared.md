# Multi-Region Database Architecture — Shared

## Purpose

Define data consistency, clock skew management, replication lag mitigation, and network latency strategies for backends and PostgreSQL databases deployed across multiple geographical regions.

## Multi-Region Challenges

When database primary nodes, read replicas, API application servers, and frontends (CDN edge) are located in different physical regions (e.g. EU-West, US-East, APAC):

1. **Replication Lag**: Asynchronous replication from Primary DB (US-East) to Read Replicas (EU-West) takes 10ms–500ms+. A user writing data to EU and immediately refreshing will hit the local EU replica and experience **Read-After-Write inconsistency** (seeing stale data or 404).
2. **Clock Skew / Drift**: Server clocks on app servers in different regions and DB servers drift out of sync. Using application server time for DB records leads to future-dated records or invalidation failures.
3. **Cross-Region Latency Amplification**: Each round-trip query across regions takes 70ms–150ms RTT. Executing N+1 queries across regions turns a 10ms operation into a 2-second bottleneck.
4. **Connection Overhead**: Opening cross-region TCP/TLS connections for every request adds 200ms+ latency penalty per request.

## Rule 1: Database Time Authority & Clock Skew

- Always use the **Database Primary Server Time** for authoritative entity timestamps (`created_at`, `updated_at`).
- Use `server_default=func.now()` in SQLAlchemy models so PostgreSQL generates timestamps on the primary database node.
- Synchronize all application servers using NTP (Network Time Protocol / Chrony).
- When validating short-lived JWT tokens across regions, configure a clock skew leeway (e.g. `jwt.decode(token, secret, leeway=10)`).

```python
from datetime import datetime
from sqlalchemy import DateTime, func
from sqlalchemy.orm import Mapped, mapped_column

class Order(Base):
    __tablename__ = "orders"
    # Required because updated_at uses onupdate=func.now() below — see
    # database/sessions.shared.md's verified MissingGreenlet finding.
    __mapper_args__ = {"eager_defaults": True}

    id: Mapped[str] = mapped_column(primary_key=True)
    # Generated by PostgreSQL primary node to prevent app-server clock drift issues
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        nullable=False,
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        onupdate=func.now(),
        nullable=False,
    )
```

## Rule 2: Read-After-Write Consistency

To prevent users from seeing stale data immediately after a POST/PUT/PATCH/DELETE operation:

- **Route Mutations & Immediate Reads to Primary**: Route all state-mutating requests and subsequent reads within a short window (e.g. 5 seconds) to the Primary Database.
- **Sticky Primary Session**: Set a cookie or response header (`X-Read-Primary-Until`) after mutations so subsequent GET requests from that client route to the primary DB node until replication catches up.

```python
from enum import Enum
from typing import AsyncGenerator
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

# Primary DB Engine (US-East) - Handles all writes and primary reads
primary_engine = create_async_engine("postgresql+asyncpg://primary.db.internal/app", pool_pre_ping=True)
# Replica DB Engine (EU-West) - Handles read-only queries
replica_engine = create_async_engine("postgresql+asyncpg://replica-eu.db.internal/app", pool_pre_ping=True)

PrimarySession = async_sessionmaker(primary_engine, expire_on_commit=False)
ReplicaSession = async_sessionmaker(replica_engine, expire_on_commit=False)

async def get_read_session(read_from_primary: bool = False) -> AsyncGenerator[AsyncSession, None]:
    session_factory = PrimarySession if read_from_primary else ReplicaSession
    async with session_factory() as session:
        yield session
```

## Rule 3: Minimize Cross-Region Round Trips

- **Eliminate N+1 Queries**: Use `joinedload` / `selectinload` or single SQL CTEs/subqueries. Executing 1 query takes 1 RTT (80ms); executing 10 queries sequentially takes 800ms.
- **Use Connection Pooling Proxies (PgBouncer / RDS Proxy)**: Deploy PgBouncer proxies in the same region as application workers to maintain warm, persistent TLS connection pools to the primary database region.

## Rule 4: Distributed Locks across Regions

- Never hold a database row lock (`with_for_update()`) while performing a slow cross-region external HTTP call.
- Complete the external HTTP call *first*, then execute a fast atomic SQL transaction at the primary database.

## Forbidden

- using application server clock (`datetime.now()`) for audit columns on multi-region deployments
- directing immediate post-mutation GET requests to asynchronous read replicas without replication lag handling
- holding database locks across multi-region external network calls
